## Scope

decision 6 waits for an owner decision on its syntax; do not invent one. The
routes to read and write mappings are M4-31b. This change gives the store, the
mapper, the applier, the suites and the wiring.

## Change

1. `group_mappings` table: `source`, `source_id`, `claim_value`, `group_id`,
   `created_by`, `created_at_ms`, unique on (`source`, `source_id`,
   `claim_value`, `group_id`). Compare claim values byte for byte (the case
   `AValueThatDiffersOnlyInCaseIsAnotherValue`).
2. `MapGroups` reads only the mappings of (`source`, `source_id`). No row for
   that pair returns `ErrNoGroupMapping`. A group of another home and a deleted
   group are never returned (check in SQL and again in Go; comment the second
   check as defense in depth).
3. `ApplyGroupClaims`: one transaction. Validate the claims at the boundary
   (limits of `GroupClaims`), load the principal (layer 4 cases), map, compute
   adds and removals for the memberships of this source and source ID only,
   apply ADR 70 rules for protected groups, write one audit entry for each
   add, removal, suspension and refusal, and one entry for unmapped values
   with a bounded list. On any error, roll back.
4. Turn every case of `RunGroupMapper` and `RunGroupClaims` into a real test.
   Remove the skip and `designOnlyRefusal` for these two suites. Keep the
   case names.
5. Wire the SQLite and PostgreSQL appliers in `area_signin.go`.

## Acceptance

  skipped case.
- Hostile tests, one for each layer, each alone:
  - boundary: 1001 values, a value of 257 bytes, a value with `\x00` and with
    `\r\n`, source `local`, empty source ID: `ErrInvalid`, nothing changed.
  - SQL: a claim value `' OR 1=1 --` maps to nothing (placeholders only).
  - authorization at point of use: a mapper row that names a group of another

  - limit: a principal that is a service principal, a break-glass account or a
    temporary administrator: `ErrNotSignInTarget`.
  - fail closed: a mapper error, a write error and an audit write error each
    change nothing; `ErrNoGroupMapping` joins no group and writes one entry.

  applier): an LDAP user with a mapped group value gets the membership with
  source `claim` and the provider ID as source ID.
