The database is the only coordination point
Holds
Achievable. Today it fails in five places: backup and restore slots, the staging name, start-up recovery, unfenced server-scope writes, and in-process stripes and TryLock (A2, B2, A3, B4, G2, G5). It also argues for replacing ADR 48's calls between instances with an epoch recorded in the database (B3).
No lease per job
Partly
No lease per job and no lease service: yes. No lease at all: no. Something must turn silence into "dead" after a timeout. The minimum is one lease per instance, which ADR 48 already accepted (A1). Claims record the owner's registration ID and a claim epoch (A5).
Durable work items claimed with SKIP LOCKED
Partly
Right for the claim, which must commit. A row lock held for a long job pins one of four pool connections, holds back vacuum, cannot fence the holder's other connections, and can deadlock invisibly with the swap. Periodic singletons need a schedule row with a conditional UPDATE, not SKIP LOCKED. On SQLite, BEGIN IMMEDIATE does the claim (A4, A5).
Long operations become durable
Partly
Ownership and state: yes. Resumable execution only at real step boundaries. A backup export restarts, because its snapshot ends with the connection. A restore needs its control rows outside the swap (B1) and a staging handle (B2) before another instance can resume it.
Cache only immutable or versioned data
Restate
Blob keys are write-once, so they are safe to cache (A8). SQL rows by serial are not, because a restore can reuse a serial; key them by the failover version. Mutable singletons need a declared staleness bound and a writer barrier (A7). The token policy cache should be a join, not a cache (A9).
groupcache-go
Not now
Not for authorization data: it has no reliable invalidation, and a lost Remove would let a revoked token keep working. For blobs, it needs the registry for peers, a peer protocol that ADR 48 d6 may forbid, and a new dependency. A peer fetch of a value of several MB costs about the same as the S3 GET it replaces. Measure a local cache first.
Hidden ceilings the direction does not fix
Watch
Audit appends lock the namespace row FOR UPDATE, and every @server write in the cluster waits on one advisory lock (C1, C2). Adding instances does not raise sign-in or per-namespace audit throughput.

A5

Stress test: SKIP LOCKED claims a work item; it does not prove the owner is alive

Strongports & adaptersDesign decision (RFC); code lands in A1–A4
Problem
Holding FOR UPDATE for a multi-minute job pins one of four pool connections, holds back vacuum for the whole cluster, dies to idle_in_transaction_session_timeout, and cannot pass PgBouncer in transaction mode. A crashed host without a TCP reset keeps the lock for about 2 hours (keepalive default). A partitioned instance whose connection drops loses the lock while it still runs on another pooled connection: a row lock does not fence the holder's other connections. If the job row lives in the swapped schema, the swap's DROP SCHEMA waits on the instance's own other connection, a cycle PostgreSQL's deadlock detector cannot see.
Deletion test
Not a module. The finding decides what A2 is: the claim commits, and liveness comes from elsewhere.
Deepening
State the honest version in the RFC: no lease per job and no lease service, exactly one lease per instance (A1). A claim is SKIP LOCKED plus owner = registration, then commit. Takeover happens when the owner registration ended plus a clock-skew bound. Every completing write checks owner or claim_epoch in its transaction, like namespace.Fence. Every expiry uses the database clock. Coordination tables are bookkeeping (B1). On SQLite, BEGIN IMMEDIATE plus UPDATE … RETURNING; SKIP LOCKED is a PostgreSQL throughput option, not a correctness need.
Tests
A worktest suite with a two-handle factory (E2): zombie write refused, takeover only after registration end, swap keeps rows.
Risk and size
Low as a decision. The risk is skipping it and building row-lock-held jobs.
Horizontal scaling
This is the scaling design. Existing leases that remain: the Pulumi update lease (protocol), the audit sink leases (C9 can remove them), the chain claim (A2 can absorb it).
ADR

The audit sink leases came with #599 and no ADR records them. ADR 64 d6 uses the instance clock. RFC 36 proposes a job lease table the owner rejected; rewrite it around this.

Durable operations on an instance registry: A2 on A1, starting with B1

This is the candidate with the most leverage.
