# TypeScript client

The repository holds a TypeScript client for the REST API under
`/api/dustpan/v1`. The generator `cmd/clientgen` writes it from the API
description. The package is `clients/typescript`. Its name is
`@opendustpan/client`.

The package is not on the npm registry yet. This page describes the package in
the repository.

## What the package has

| Part | Content |
| --- | --- |
| Types | One type for each schema of the description. An enum with a list that can grow keeps a value that the client does not know. A closed enum refuses such a value. |
| Validators | One validator for each schema. The client runs the validator on every answer. A validator copies the members of the schema and drops all others. |
| Operations | A table with one entry for each operation. An entry has the method, the path, the success statuses, the headers of the operation and the validator of the answer. |
| Client | A class with one method for each operation. |
| Transport | An interface with one method, `send`. The default transport uses the global `fetch` and sends a bearer token. |

The package has no dependency. It needs Node 20 or a browser that has `fetch`.

## Use the client

```ts
import { Client, createFetchTransport } from "@opendustpan/client";

const client = new Client(createFetchTransport({ baseUrl: "https://dustpan.example.com", token }));
const { body, etag } = await client.getProfile({ path: { namespace: "dev", profile: "base" } });
```

Each method takes one argument. Its members are `path`, `query`, `body`,
`ifMatch`, `idempotencyKey` and `signal`. A member is there only if the
operation takes it. Each method returns the success status, the `ETag` header
and the validated body.

An operation that takes `Idempotency-Key` gets a new random key from the
default transport. Give `idempotencyKey` to send your own key.

## What the client accepts

The client accepts an answer only when both of these are true:

- The status is one of the success statuses that the description gives for the
  operation. The client refuses a status such as 202 or 204 when the
  description gives 200 only, also when the body is correct. An operation that creates on a first
  write and replaces later, such as `putGitHostApp`, gives 200 and 201.
- The body matches the schema. A member of the wrong type, a `null` where the
  schema does not allow it, a missing member and an integer that a JavaScript
  number cannot hold exactly are errors.

## Errors

Every error is an `ApiError`. Its `kind` says what failed:

| `kind` | Meaning |
| --- | --- |
| `server` | The server answered with a status that is not a success status. `errorCode` and `errorArgs` come from the error document. |
| `invalid` | The server answered, but the answer does not match the description. `status` is the status of the answer and `path` is the JSON path of the first wrong value. |
| `transport` | No answer came. |
| `request` | The call does not fit the operation. Examples: an empty path value, a missing `If-Match` that the operation needs, or a missing required query parameter. The client sends nothing. |

## Use your own transport

A transport is an object with a `send` method. It gets the operation, the
path values, the query, the body and the values of the headers. It builds the
request, adds the credential that `spec.security` asks for, and returns the
status, the parsed body and the `ETag` header of a 2xx answer. For any other
status it throws an `ApiError` of kind `server`. The client then validates the
status and the body.

The default transport:

- sends the token only to operations that need a sign-in, and only to the
  origin of the base URL.
- follows a redirect itself, except in a browser, and only when the target is
  inside the base URL (the same origin and the base path). A redirect to
  another origin or outside the base path is an `ApiError` of kind `transport`.
  The transport then sends no second request. In a browser, the transport
  cannot read the target of a redirect, so any redirect is a `transport` error.
- refuses a path value that is empty, `.` or `..`.
- refuses an answer longer than 16 MiB.
- does not retry a request.

## Make the package again

The generator writes the package. Do not edit a file that has the header
`Code generated by clientgen`.

```sh
make clients-generate   # write clients/typescript from the description
make clients-check      # fail if the files differ from a fresh run
make clients-ts-test    # compile with tsc and run the tests, needs Node 22 and tsc
```

The generator owns `src/`, `package.json` and `tsconfig.json`. A file there
that a run does not give, also a file without the header, makes
`make clients-check` fail with `stray: <path>`, and `make clients-generate`
refuses to write until you remove the file. Other files, for example
`README.md` and `test/`, stay as they are.

`make clients-check` is part of `make lint`. The program has a stable command
line:

```sh
go run ./cmd/clientgen -target typescript -description openapi.json -out clients/typescript
```

| Flag | Meaning |
| --- | --- |
| `-target` | The template set. `typescript` is the only one. |
| `-description` | The path of the API description. |
| `-out` | The output directory. |
| `-package` | The package name. The default is `@opendustpan/client`. |
| `-client-version` | The package version. The default is `info.version`. Its major and minor parts must be those of `info.version`. |
| `-server-release` | The server release. Before the first release, use the commit. The package records it in `metadata`. The default is `development`. |
| `-server-commit` | The Git commit of the server, 40 lowercase hexadecimal digits. The package records it in `metadata.serverCommit`. The default is `development`, for a run that is not a release. |
| `-check` | Write nothing. Exit with 1 and list the differences. |

The package records the SHA-256 of the description in `metadata.descriptionSha256`.
`info.version` alone is not a safe pin. The subpath
`@opendustpan/client/description` exports `description`, the text of the
description. The SHA-256 of its UTF-8 bytes is `metadata.descriptionSha256`.
The root of the package does not export it, so an import of the client does
not load the text:

```ts
import { description } from "@opendustpan/client/description";
```

## Error answers by code

The package exports the type `ErrorAnswer` and the validator `decodeErrorAnswer`.
`ErrorAnswer` is the union of one type for each code that has arguments, for
example `LockLockedError`, and `ErrorResponse`. The validator reads
`errorCode`. For a code that has its own type, it validates the arguments with
their types and refuses an answer with an argument that is missing or wrong, as
it refuses any other answer that does not match the description. For any other
code, also a code that the description does not list yet, it gives the shape of
`ErrorResponse`. The validator gives the exact type of each answer. A test of `errorCode` in your code narrows to the variant and to `ErrorResponse`, because `errorCode` is an open enum.
