# RFC 69. Community channels: announce list, Discussions, and a later chat

Status: discussing.

## Problem

The project has no place yet for people to ask questions, and no list that
tells users about releases, security pre-announcements and breaking changes.
Questions and bug reports both reach the issue tracker, so the tracker holds
work that is not a bug.

## Options

1. **Announce-only mailing list.** Low volume. It carries releases, security
   pre-announcements (`SECURITY.md`) and breaking changes. Nobody posts to it
   except the project.
2. **GitHub Discussions.** Public questions and answers. Bugs stay in issues.
3. **A chat with a public archive**, such as Zulip or Matrix. Later, and only
   when users ask for it.
4. **Slack.** Not now.
5. **Do nothing.** Users keep asking in issues.

## Proposal

Options 1 and 2 now, option 3 when users ask for it, and no option 4. The
announce list and Discussions answer two needs that the issue tracker does
not meet. A chat adds a second place to watch, so it waits for a demand.

## Open questions

None. The owner chooses the host of the announce list and the date of the
setup when the owner sets up the channels.

## Outcome

The owner approved options 1 and 2, and the decision to wait for option 3, on
2026-10-13.

The channels wait for the owner to set them up at a later date. Discussions
is turned on in the repository settings, and the announce list needs a host.
Until then, no document names an address or a link for either one. Nothing
waits on this RFC.
